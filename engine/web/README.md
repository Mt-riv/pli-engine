# ブラウザ版

`pli-engine` をブラウザだけで動かす **HTML 1枚**。
サーバもインターネット接続も要らない。

> **使い方の手引きは [`../../docs/browser-manual.md`](../../docs/browser-manual.md)。**
> この文書は作りの説明（なぜ HTML 1 枚なのか、何を固定してあるか）。

## 配る・使う

ビルドすると `dist-web/index.html` が1つだけできる。
**このファイルを渡して、ダブルクリックで開いてもらえばそれで動く。**

```bash
npm install
npm run web:build     # dist-web/index.html（約124KB）ができる
open dist-web/index.html   # macOS。Windows は start、Linux は xdg-open
```

インストールも展開も不要。ブラウザがあれば動く。

### ローカルサーバで使いたい場合

```bash
npm run web:dev       # 開発サーバ（編集が即反映される）
npm run web:preview   # ビルド結果を確認
```

## なぜ HTML 1枚なのか

`<script type="module" src="...">` で外部ファイルを読む形にすると、
`file://` で開いたときに CORS で弾かれて動かない。
そのため出力を IIFE にして HTML に直接埋め込んでいる
（`vite.config.ts` の `singleFile` プラグイン）。

埋め込む位置も重要で、インラインの classic script は module と違い
遅延しないため、`<head>` に置くと DOM 生成前に走って動かない。
`</body>` の直前に入れている。これらはテストで固定してある。

## 機能

- **外部依存なし** — CDN に繋がないのでオフラインで動く
- 行番号付きエディタ、診断をクリックすると該当行へジャンプ
- URL のハッシュにソースを載せて共有
- `localStorage` に自動保存
- サンプル12本（すべて実行できることをテストで保証している）
- **Snippet38本** — ヘッダの「Snippet…」から挿入する。
  挿入位置の字下げに合わせて貼られる
- **テストモード** — 主手続きが無く `TEST_` 手続きがあるファイルは、
  「実行」でテストとして走り、成功・失敗の一覧を出す
  （[`../../docs/test.md`](../../docs/test.md)）
- **ファイル欄** — `%INCLUDE` の取り込み元と入出力の相手を書く。
  `::: 名前` の行で区切る。**プログラムが書き出したファイルもここに現れる**
- **標準入力欄** — `GET LIST` / `GET EDIT` が読む内容（SYSIN）
- **検査ボタン** — 実行せずに Linter をかける（[`../../docs/lint.md`](../../docs/lint.md)）

Monaco などのエディタを使わず `textarea` で作っているのは、
CDN への接続を不要にしてオフラインで動かすため。

## file:// で開いたときの制約

ブラウザは `file://` を安全なコンテキストとして扱わないため、
いくつかの機能が使えない。どれも動作に支障が出ないようにしてある。

| 機能 | file:// での挙動 |
|------|----------------|
| `localStorage` | 使えないことがある。保存は諦めて動作は続ける |
| クリップボード | 使えない。共有ボタンは URL のハッシュを更新するので、アドレスバーからコピーできる |

共有ボタンがクリップボード不在時に無反応にならないことはテストで固定してある
（オプショナルチェーンで連鎖全体が短絡し、フォールバックが動かない不具合があった）。

## 無限ループ対策

ブラウザには別プロセスが無いので、エンジン側で上限を設けている。

- 実行する文の数: 500万
- 出力: 100万文字

`do while('1'b); end;` のような終わらないループも 0.1 秒ほどで停止する。
文の数を数えるだけでは本体が空のループを取り逃すため、
ループの周回でも数えている。
