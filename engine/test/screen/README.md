# 画面（MFS）のゴールデンテスト

ここの `*.screen` は、**IBM の仕様文書を正として組んだ画面像**を
バイト単位で固定したもの。`screen.test.ts` が一致を要求する。

## `test/golden/` との違い — 出どころが違う

| | `test/golden/` | ここ（`test/screen/`） |
|---|---|---|
| 正の根拠 | **実在の PL/I 処理系の出力**（実機） | **IBM の仕様文書** |
| 取り直す手段 | 別リポジトリ `pli-oracle` | 無い（仕様を読み直す） |
| `.why` の 1 行目 | `実機: Iron Spring PL/I …` | `IBM 仕様に基づく（実機の出力ではない）` |

MFS と DL/I には突き合わせる実機が無い。**IMS は z/OS 専用**で、
手元で動かせる実装（商用の移行製品しかない）も入手できない。
だから出処を取り違えないよう、置き場所と `.why` の 1 行目を分けている。
`screen.test.ts` は 1 行目の書き出しまで機械で確かめる。

## ファイルの組

| ファイル | 役目 |
|---------|------|
| `<名前>.pli` | 走らせるプログラム |
| `<名前>.mfs` | 書式定義（`FMT` … `FMTEND` / `MSG` … `MSGEND`） |
| `<名前>.files` | 付随ファイル。`::: 名前` 区切りで PSB・DBD・データを並べる |
| `<名前>.keys` | 端末の操作の台本（書き方は `src/tm/keys.ts` の冒頭） |
| `<名前>.screen` | 期待する画面像（バイト一致） |
| `<名前>.why` | **何を固定しているか**（必須。無いと落ちる） |

PSB の名前は `<名前>.files` に置いた `*.psb` から決まる。
入出力 PCB（`PCB TYPE=TP` か `CMPAT=YES`）を含まない PSB では動かない。

## 取り直す

```
npx tsx scripts/gen-screen.ts <名前>
```

**出力を見て、どの規則でそうなるのかを確かめてから置くこと。**
確かめずに置いた期待値は「この処理系の今の出力」にすぎず、
固定する意味が無い。確かめた規則は `.why` に書く
（後から読む人が、仕様のどこを見ればよいか分かるように）。

## 今ある組

| 名前 | 何を固定しているか |
|------|------------------|
| `inquiry` | 位置と属性、属性バイトの 1 桁、`JUST` / `FILL`、`PFK` の固定文字、`DATE2`、`/FORMAT` |
| `conv` | 会話型の SPA（`LL` + `ZZZZ` + コード + 作業域）と、コードを空白にして終わる約束 |
| `table` | `DO` / `ENDDO` の繰り返しと通し番号（FMT 側と MSG 側で名前が噛み合う） |
| `attrs` | `ATTR=YES` の 2 バイト（置き換え・論理和・カーソル要求）と `DSCA` |
