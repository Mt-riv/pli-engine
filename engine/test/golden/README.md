# ゴールデンテストの期待値

ここの `*.expected` は、**実在の PL/I 処理系の出力**をバイト単位で固定したもの。
`golden.test.ts` が一致を要求する。

## ファイルの組

| ファイル | 役目 |
|---------|------|
| `<名前>.pli` | 走らせるプログラム |
| `<名前>.expected` | 期待する標準出力（バイト一致） |
| `<名前>.why` | **出処**。なぜその出力が正しいと判断したか（必須） |
| `<名前>.in` | 標準入力（任意） |
| `<名前>.args` | 主手続きの引数。1 行 1 引数（任意） |

`.why` が無いと `golden.test.ts` が落ちる。出処の無い期待値は
「この処理系の今の出力」にすぎず、固定する意味が無いため。

## 取り直す

**推測で `.expected` を書いてはいけない。**

取り直す道具は**別のリポジトリ `pli-oracle`（非公開）**にある。
突き合わせ用の処理系（Iron Spring PL/I）は 32 bit x86 のバイナリで、
arm64 Mac では動かない。動かす環境の用意・費用・配布物の扱いもそちらが
受け持つので、「ブラウザ 1 枚で動く」というこのリポジトリの前提には
持ち込んでいない。**ここに置くのは固定された期待値と、その出処だけ。**

手順（環境を建てる → 挙動を見る → 期待値を取り直す → `.why` を書く →
ここで `npm test` → 環境を消す）は `pli-oracle` の README の
「次に実機が要るとき」にある。

```bash
cd ../pli-oracle            # 別リポジトリ。用意の仕方はそちらの README
PLI_ENGINE=../pli-engine ./regen.sh widths
```

このテスト自体は `pli-oracle` が無くても動く（固定済みの
`.expected` と比べるだけ）。CI も同じ。

## 除算は入れない

除算の結果の桁数は**最大精度**で決まる。実機（Iron Spring）の 10 進の
最大精度は 18、この処理系は IBM PL/I for MVS and VM 1.1 に合わせて 15 なので、
どんな除算もバイト一致しない。意図的な差で、理由は
`engine/README.md` の「実機と違えている点」にある。

## IMS/DB（DL/I）はここに置かない

IMS は z/OS 専用で、突き合わせる相手が無い。DL/I は IBM の仕様文書を正とし、
各ステータスコードの意味を `dli-engine.test.ts` と `dli-fixes.test.ts` の
コメントに引用して担保している。担保の仕方が違うので混ぜない。
