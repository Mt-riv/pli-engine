## 設計上の最重要事項: 字句解析はキーワードを判定しない

PL/I には予約語が無く、次が合法なコードである。

```pli
IF IF = THEN THEN THEN = ELSE;
```

「IF と THEN が等しければ THEN に ELSE を代入する」という意味になる。
したがって語がキーワードか識別子かは**文脈でしか決まらない**。
字句解析は一律に `word` を返し、判断は構文解析に委ねる。

この性質を最初のテストに据えてあるので、素朴なキーワードテーブルに
後戻りできない構造になっている。

## PUT LIST の出力書式

推測ではなく、実在の PL/I 処理系の出力と突き合わせて導いた。

| 要素 | 規則 |
|------|------|
| `FIXED DEC(p,q)` のフィールド幅 | **p + 3** |
| `FIXED BIN(p,q)` のフィールド幅 | 10進桁 `ceil(p·log10 2) + 1` に **+3**（BIN(31)→14、BIN(15)→9） |
| 項目の配置 | **24 桁ごとのタブストップ**。数値は右詰め、文字は左詰め |
| 行幅 | **120 桁**。次の項目が収まらなければ現在行を120 桁まで空白で埋めて改行 |
| 項目の後ろ | 空白1個 |

根拠の一例: 九九（`put list` を9 回）の出力は1行目が **120 桁（5項目 = 5×24）**、
2行目が **87 桁（= 3×24 + 14 + 1、4項目）** になる。

## 文の種別判定（構文解析の核）

予約語が無いため、文がどの種類かは文脈でしか決まらない。採用した規則:

> 先頭が「参照（語 + 省略可能な添字）」に続いて `=` なら**代入文**。
> そうでなければ先頭語を**文キーワード**として解釈する。

これで次がすべて正しく解釈される。

| 入力 | 解釈 |
|------|------|
| `IF IF = THEN THEN THEN = ELSE;` | IF 文（条件 `IF=THEN`、本体 `THEN=ELSE`） |
| `THEN = ELSE;` | 代入文 |
| `do = 5;` | 代入文（`do` という変数へ） |
| `do i = 1 to 9;` | DO 反復文 |
| `a(2,3) = 7;` | 代入文（添字付き） |
| `put list(1);` | PUT 文（`(` で始まるが `=` が続かない） |

## 実物から学んだこと

外部の参照プログラム（上記の `numwrd.pli` など。リポジトリには入っていない）を
実際に解析して判明した、仕様書だけでは気付けない点。

1. **改行以外の、0x20 未満の制御文字は無視しなければならない** —
   古いソースは末尾に 0x1A（DOS の EOF マーカー）を持つことがある。
   仕様にも
   "Other than newlines, characters lower in the collating-sequence
   than spaces ('20'x) are ignored." と明記されている
2. **`OPTIONS` は空白区切り** — `options(main reentrant)`。カンマではない
3. **配列は下限を明示できる** — `dcl ones(0:9) char(8)` は 0..9 の10要素
4. **宣言の括弧は2種類ある** — 名前直後は次元 `b(3,3)`、属性語の後は精度 `bin(31)`
5. **`INITIAL` は値のリストを取る** — `init(1,2,3)`

## 算術の実装

**FIXED DECIMAL を10進固定小数点として正確に扱う**。値は「尺度付きの
BigInt」で保持する（DECIMAL なら実値 = v / 10^q、BINARY なら v / 2^q）。
JS の number（2進浮動小数）で代用すると `123.45 * 6.7 = 827.115` が
一致しない。

精度規則も PL/I の規定どおりに実装した。いずれも出力幅から裏が取れている。

| 演算 | 規則 |
|------|------|
| 加減算 | p = max(p1-q1, p2-q2) + max(q1,q2) + 1, q = max(q1,q2) |
| 乗算 | p = p1+p2+1, q = q1+q2 |
| 除算 | p = N, q = N - ((p1-q1) + q2)（N は最大精度: DEC 15 / BIN 31。実機の DEC は 18 で、ここは意図的に違う） |
| 基数混在 | **BINARY に変換する**（尺度も移す。10 進 1 桁 ≒ 2 進 3.32 桁。端数は **0 方向へ切り捨て**。実機で確認） |
| `ROUND` | 結果の精度は「整数桁 + n + 1」、尺度は n。BigInt で直接丸める（0 から遠い側へ）。実機で確認 |
| `**` | 指数が整数で 0 以上なら FIXED（p = (p1+1)*y - 1、q = q1*y）。小数・負・**精度が最大を超えるとき**は FLOAT。実機で確認 |
| `MOD` | p = min(N, p2-q2+max(q1,q2))（結果は第2引数より小さいため） |
| FLOAT との混在 | **FLOAT が優位**。結果の精度は両辺の大きい方（FIXED の辺も数に入る）。実機で確認 |

「基数混在は BINARY」が正しいことは、13 の階乗がちょうど溢れること
（13! = 6,227,020,800 > 2³¹−1）で確認できる。DECIMAL のままなら
15 桁に収まるので溢れない。

## 作る途中でつまずいた点

単体テストは通るのに、まとまったプログラムでは合わない——という差が有益だった。

1. **プログラム終了時に最終行を改行で終端する** — これ1つの修正で
   出力の一致が大きく進んだ
2. **引数名の `DECLARE` は属性宣言であって新変数ではない** —
   `proc(n)` の本体の `dcl n fixed bin(31);` を新変数として 0 で
   初期化すると引数が失われる。再帰と入れ子手続きがこれに依存する
3. **`LENGTH` / `INDEX` は `FIXED BIN(15,0)` を返す** — 出力幅 9 から分かる
4. **`MOD` は整数剰余** — 除算の精度規則を使うと `MOD(17,5)` が 0 になる
5. **`FLOAT DEC(6)` のフィールド幅は p+8** — ` 3.50000E+0000` で14桁

| 機能 | 必要になった題材 |
|------|----------------|
| `PUT EDIT` と書式項目（`A` / `F(w,d)` / `E` / `B` / `X` / `COLUMN` / `SKIP` / 反復係数） | `PUT EDIT` の例、数値の読み上げ |
| データリスト中の**配列の自動展開** | 対角成分の別名 |
| `GET STRING ... EDIT` / `... LIST` | `PUT EDIT` の例、数値の読み上げ |
| `DEFINED` + iSUB（別名定義） | 対角成分の別名 |
| ファイル宣言（`dcl sysprint print;`）※標準出力として受け付ける | 数値の読み上げ |
| 主手続きの引数（コマンドライン引数） | 数値の読み上げ |
| 配列の評価（多次元、下限付き、`INIT` リスト） | `PUT EDIT` の例、数値の読み上げ |

### EDIT と LIST の違い

同じ行・桁を共有するが書き方が違う。

| | タブストップ | 末尾の空白 |
|--|------------|-----------|
| `PUT LIST` | 24 桁ごと | 項目ごとに1個付く |
| `PUT EDIT` | 使わない（書式の指定どおり） | 付かない |

根拠: `put skip edit('b: ',b)(a,(9)f(4))` の出力が
`3 + 9×4 = 39` 桁ちょうどで、末尾に空白が無い。

### DEFINED の別名セマンティクス

```pli
dcl b(3,3) bin fixed init(1,2,3, 4,5,6, 7,8,9);
dcl d(3)   bin fixed def (b(1sub,1sub));
```

`d` は記憶域を持たず `b` の対角成分への別名になる。`1sub` は
「別名側の第1次元の添字」を表す仮変数なので、`d(i)` は `b(i,i)` を指す。
読み書きの両方が基底変数へ転送される必要があり、対角成分の別名は
`get string(t) edit(d)(f(5))` で `d` に書いて `b` の変化を出力している。

## 制御構造・構造体・条件

| 機能 | 備考 |
|------|------|
| `SELECT` / `WHEN` / `OTHERWISE` | `SELECT(expr)` と `SELECT;` の両形式 |
| `LEAVE` / `ITERATE` | 内部例外で制御 |
| `DO` の複数指定 | `do i = 1 to 3, 7 to 9;` / `do i = 1, 5, 10;` |
| `GOTO` と文ラベル | 文列からラベルを探して飛ぶ。見つからなければ上位へ伝播 |
| 構造体 | レベル番号から修飾名（`REC.ADDR.CITY`）を組んで葉を登録。次元は**葉に付ける**（`2 a(3) fixed bin(15)`）。構造体そのものに付けた次元（`1 tbl(3)`）は宣言の時点で断る |
| `ON` 条件 / `SIGNAL` | ERROR は再開可能でない扱い |
| `BEGIN` ブロック | 独自の名前の有効範囲を持つ |
| 配列式 | `c = a + b` / `c = a * 2` を要素ごとに計算 |
| `SUBSTR` 疑似変数 | `substr(s,3,2) = 'XY'` |
| `%REPLACE` と一覧制御文 | トークン列の段階で処理（文字列リテラルを誤置換しない） |
| 宣言の既定 | `dcl x;` のように型を 1 語も書かなければ、**暗黙宣言と同じ規則**（名前の先頭文字。I〜N は FIXED BIN(15,0)、それ以外は FLOAT DEC(6)）。`FIXED` や基数・精度を書けば FIXED の既定 |
| 引数 | **参照渡し**。宣言した属性が渡した値と違うときだけ一時変数（ダミー引数） |
| `RETURNS` | `RETURN` の値を宣言した型へ合わせる |
| 組込関数（21 種） | 算術 `ABS` `CEIL` `FLOOR` `ROUND` `TRUNC` `SIGN` `MOD` `DIVIDE` `MAX` `MIN` ／ 文字列 `LENGTH` `INDEX` `SUBSTR` `REPEAT` `TRANSLATE` `VERIFY` ／ 配列 `LBOUND` `HBOUND` `DIM` ／ ポインタ `ADDR` `NULL`。これ以外の PL/I の組込関数は**名指しで断る**（`UNIMPLEMENTED_BUILTINS`） |

### 戻り値型と精度

出力フィールド幅から逆算した。

| 組込関数 | 結果の型 | 幅 |
|---------|---------|-----|
| `LENGTH` / `INDEX` / `VERIFY` / `SIGN` | `FIXED BIN(15,0)` | 9 |
| `LBOUND` / `HBOUND` / `DIM` | `FIXED BIN(31,0)` | 14 |
| `CEIL` / `FLOOR` | `FIXED(min(N, max(p-q,1)+1), 0)` | `ceil(2.1)` で 5 |
| `DIVIDE(a,b,p,q)` | `FIXED DEC(p,q)` | p+3 |
| `MOD` | `p = min(N, p2-q2+max(q1,q2))` | `mod(17,5)` で 4 |

`CEIL` を「切り捨ててから 1 を足す」と実装すると加算の精度規則で
p が広がり、出力幅が合わなくなる。結果精度を直接構成する必要がある。

### 文字比較は照合順序（文字コード順）

`'Z' < 'a'` は真（0x5A < 0x61）。JS の `localeCompare` はロケール依存で
これを偽にすることがあるため使えない。短い側は空白で埋めて比べる。

### ON 条件の扱いを規定からずらした

**突き合わせに使った処理系**で計測すると、こうなった。

- `ON ZERODIVIDE` の ON 単位から正常復帰すると演算が再試行され、
  条件を直さないかぎり無限ループになる（実測で 18 万行出力し、60 秒で打ち切った）
- `ON ERROR` の ON 単位から正常復帰するとプログラムが終了する
  （ERROR は再開可能でない）

**この処理系は前者を規定どおりにしていない。** 計算条件
（`ZERODIVIDE` / `FIXEDOVERFLOW` / `SIZE`）の ON 単位を実行したあとは、
演算を再試行せず `ERROR` へ進めて終える（`interp.ts` の `raise`）。
止まらないプログラムを作るより、止めて報告する方が学習の役に立つと判断した。
ここは**意図的な非互換**なので明記しておく（終了コードは 1）。

このためテストでは `SIGNAL` を使う形にし、
マニフェストに `expectRuntimeError` を立てて標準出力の一致だけを要求している。

### 発火する条件はこれだけ

`ON` はどんな条件名でも構文として受けるが、処理系が起こすのは次の 6 つ。

| 条件 | 起こす場所 |
|------|-----------|
| `ERROR` | 他の条件からの連鎖、`SIGNAL ERROR`、`SELECT` でどれにも合わない |
| `ZERODIVIDE` | 0 除算（`/`、`MOD`、`DIVIDE`。FIXED と FLOAT の両方） |
| `FIXEDOVERFLOW` | 固定小数点の桁あふれ |
| `SIZE` | 代入先に収まらない |
| `SUBSCRIPTRANGE` | 添字が宣言の範囲外 |
| `CONVERSION` | 文字から数値への変換に失敗 |
| `ENDFILE(f)` | 入力が尽きた |
| `UNDEFINEDFILE(f)` | ファイルを開けない |

これ以外の条件名（`OVERFLOW` / `UNDERFLOW` / `STRINGRANGE` / `ENDPAGE`）に
`ON` 単位を置いても構文は通るが、処理系がその条件を起こさないので
**実行されない**。ここは未実装である。

`ON ... SYSTEM;` は既定動作へ戻す（それまでに置いた ON 単位の解除）。
空の ON 単位を置くのとは違い、**復帰して続行しない**。

`SUBSCRIPTRANGE` と `CONVERSION` は、ON 単位が置かれていなければ
従来どおりの実行時誤り（「添字が範囲外です」など）になる。
条件名だけを出すと何が起きたか分からないため。

## 実装していないもの

| 機能 | 理由 |
|------|------|
| 索引・直接編成（`KEYED` / `REGIONAL`） | 学習の題材としてまれで、実装量が大きい |
| `AREA` / `OFFSET` | `BASED` があれば大半の題材が書ける |

| 3270 のデータストリーム・DBCS・ページング | 下の「画面入出力（MFS）」の節を参照 |

未実装の属性や文に当たると、何が未実装かを名指しで報告する。

## 実機と突き合わせて決めたこと

出力書式と精度規則は実在の PL/I 処理系（**Iron Spring PL/I 1.4.1** / Linux i386）の
出力から導いている。固定した期待値は `test/golden/`（`.why` に出処を書く規約で、
取り直す道具は別リポジトリの pli-oracle にある）。

長く「推測で埋めない」として保留していた 3 点を、2026-10-10 に実機で確かめた。
**2 つは実装が間違っていた。**

| | 実機 | この処理系（修正後） |
|---|---|---|
| 基数混在の端数 | **0 方向へ切り捨て**。`(i*0.1)*16` が 1（四捨五入なら 2）、負でも `(i*(-0.1))*16` が -1（床なら -2） | 同じにした（以前は四捨五入） |
| `F(w,d)` の丸め | **0 から遠い側へ丸める**。1.26→1.3、**1.25→1.3**（偶数側ではない）、-1.25→-1.3。`F(w)` は 0 桁として丸める（1.99→2） | 同じにした（以前は切り捨て、`F(w)` は値をそのまま出していた） |
| `F` 書式の桁あふれ | **右から w 文字**を残す。上位桁も符号も黙って落ちる（-12345 を `f(4)` で `2345`）。条件は上げずに続行する | 元から一致していた |

**丸めは「書式の性質」で、代入の性質ではない。** 同じ 1.26 が
`dcl y fixed dec(5,1)` への代入では 1.2（切り捨て）、`f(6,1)` の出力では 1.3 になる。
この処理系は両方を `assignTo` で実装していたので、F 書式が切り捨てになっていた
（`roundForFormat` に分けた）。

同じ機会に周辺も確かめ、**さらに 4 つ誤りが見つかった**。
どれも「推測で決めていた」ところである。

| | 実機 | この処理系（修正後） |
|---|---|---|
| `ENDFILE` の回数 | 入力 `"12 34"` に `get list(a,b)` で **1 回**（末尾に届いた読み取りで上がる）。入力 `"12"` だと **2 回**（上記＋データの無い b の分） | 同じにした（以前は 1 回だけ） |
| 読めた値 | `"12"` のとき **a=12 / b=0**。読めた分は代入される | 同じにした（以前は**読めた a も捨てて** 0 にしていた） |
| `ROUND` の結果の精度 | **整数桁 + n + 1**。`dcl x fixed dec(5,1)` に `round(x,3)` の出力幅が 11（p=8, q=3）。1 桁多いのは丸めが桁上がりするため（`round(9.9,0)` は 10） | 同じにした（以前は +1 が無く、尺度も n に揃えていなかったので `round(x,3)` が `12.5` だった） |
| `**` が FLOAT に落ちる条件 | 規定の精度 p = (p1+1)*y - 1 が**最大精度を超えると FLOAT**。`2**9` は FIXED の 512、`2**10` は FLOAT の `1.0E+0003` | 同じ規則にした（以前は整数の指数なら必ず FIXED で、精度を黙って丸めていた）。境目は最大精度の違いの分だけ早い |
| FLOAT の結果の精度 | 両辺の精度の**大きい方**。FIXED の辺も数に入る（`4**1.5` は FLOAT DEC(2) で幅 10） | 同じにした（以前は FLOAT の辺だけ見ていたので幅 9） |

**確かめて「合っていた」もの**も記録しておく（推測で直していた箇所なので）:
`ROUND` の丸めの向き（0 から遠い側）、ビット演算（ビットごと・短い側を `'0'B` で
埋める・結果長 = max）、`**` の小数指数（FLOAT）、`2.0**3` の精度（p=8, q=3）、
`FIXED BIN` の除算（`bin(31)/3` が **整数の 2**。レビューで「2.33 になるべき」と
指摘された点だが、実機も 2 を返す）。

golden の `mixed-radix` / `mixed-radix-neg` / `fmt-round` / `fmt-noprec` /
`fmt-overflow` / `dec-assign` / `getlist-exhausted` / `getlist-short` /
`round-scale` / `power` / `bin-division` が、これらをバイト一致で固定している。

### 実機の側が壊れていたもの

突き合わせの相手も完全ではない。次は**実機に従わなかった**。

| | 実機 | この処理系 |
|---|---|---|
| `^`（NOT） | **効かない**。`^'1100'B` が `'1100'B`、`if ^('1'b)` が真 | 規定どおり反転する（`'0011'B`） |
| `2**(-1)` | `_pli_EXP` の中で `ERROR` になり落ちる | 0.5 を返す（規定どおり FLOAT で計算） |
| 末尾に改行の無い入力 | ストリーム入力が `_pli_BufI` の中で `ERROR` になる | 最後の項目まで読める |

いずれも IBM の規定と照らして実機側の誤りと判断した。
`^` は規定の NOT 演算子で、効かなければ条件式が全部壊れる。

## 実機と違えている点

突き合わせの相手（Iron Spring）と**意図的に違えている**ところ。
どちらも実機を見たうえでの判断で、理由を書いておく。

| | 実機 | この処理系 | なぜ |
|---|---|---|---|
| 10 進の最大精度 | **18 桁**。`put list(1/3)` が `0.33333333333333333`、`dcl b fixed dec(18)` も通る | **15 桁**。`1/3` は `0.33333333333333` | 互換の目標は IBM PL/I for MVS and VM 1.1 で、そこでの上限が 15 桁。実機側の 18 はその拡張。表明の窓 `FIXED DEC(15,5)` と文書の「15 桁」もここに揃えている |
| レコードの区切り | **`RECSIZE` バイトずつ**。改行もデータの 1 バイトになる（`"ab\ncdef\n"` を `RECSIZE(4)` で読むと `"ab\nc"` と `"def\n"`） | **1 行 1 レコード**。ただし `RECSIZE` より長い行は `RECSIZE` ごとに切る | 仮想ファイルはブラウザのテキスト欄で打ち込んで編集するもので、改行をデータにすると利用者の意図と食い違う。DL/I の記憶形式と同じ方針。長い行を切り捨てない規則にしたので、**改行の無いファイルでは実機と一致する** |
| `GET LIST` のレコード境界 | **区切りと見ない**。`"12\n34\n"` を `get list(a,b)` で読むと a に `1234` が入り、b は 0（改行をまたいで数字が繋がる） | **区切りと見る**。a=12 / b=34 | PL/I の規定では「新しいレコードの始まりは空白と同じ」。実機側の挙動は規定から外れていて、こちらを真似すると改行区切りのデータが読めなくなる |
| `%INCLUDE 'ファイル名'`（文字列形式） | **解決しない**（取り込まれず、識別子が既定属性の未宣言変数になる。診断も出ない） | 受け付ける | ブラウザと VSCode では「ファイル名」で指すのが自然で、識別子形式（`%INCLUDE decls;`）だけでは手元のファイルを指せない。**この処理系の拡張**で、実機にこの形は無い |

除算の結果の桁数は最大精度で決まるため、**どんな除算もゴールデンでは
バイト一致しない**。`test/golden/decimal.pli` に除算を入れていないのはこのため。

実機側の制限で確かめられなかったこと: **末尾に改行の無い入力**は
実機のストリーム入力が `ERROR` で落ちる（`_pli_BufI` の中で上がる）。
この処理系は最後の項目まで読めるので、ここは突き合わせていない。

## `%INCLUDE` とホスト抽象

外界（取り込み元のファイル、入出力の相手）への口は `src/host.ts` の
`PliHost` 1 つにまとめてある。`src/` に `node:fs` を持ち込むと
「HTML 1 枚で配れる」形が壊れるため。

| 呼ぶ側 | 渡すもの |
|--------|---------|
| ブラウザ版 | 画面の「ファイル」欄に書いた仮想ファイル（`MemoryHost`） |
| CLI | 実ファイル（`scripts/node-host.ts`。`node:fs` はここだけ） |
| VSCode Extension | 開いているファイルの隣とワークスペース直下 |
| テスト | その場で作ったオブジェクト |

```pli
%include 'DECLS.inc';      /* 文字列 */
%include decls;            /* 名前（拡張子は .inc .pli などを順に試す） */
%include syslib(dsa);      /* ライブラリ指定。括弧の中の名前を使う */
%include a, b;             /* まとめて */
```

**取り込んだトークンには取り込み元の名前を持たせている。** 付けないと
取り込んだ先の誤りが主ファイルの行として報告され、診断が嘘になる。
診断の `file` に入り、VSCode でもブラウザ版でも
`DECLS.inc 2行5桁: ...` のように出る。

循環取り込みと深すぎる入れ子（16 段）は誤りとして止める。
放っておくと止まらないので、必ず誤りとして止める方針。

`DCL f ENTRY;` も受け付ける。ユーザー定義の実体が別ファイルにある場合は呼べないが、
取り込んだ宣言群に外部手続きが含まれていても Linter が
誤検出を出さないようにするため。

## ストリーム入出力

```pli
dcl inp file stream input;
dcl rep file stream output print;
dcl done bit(1);
dcl value fixed bin(31);

done = '0'b;
on endfile(inp) done = '1'b;
open file(inp) input, file(rep) output linesize(80);

do while(^done);
  get file(inp) list(value);
  put file(rep) skip list(value);   /* 読めた値は必ず出す */
end;

close file(inp), file(rep);
```

| 対応 | 内容 |
|------|------|
| 文 | `OPEN` / `CLOSE` / `GET` / `PUT`（`FILE` 指定、省略時は SYSIN / SYSPRINT） |
| 指定 | `SKIP` / `PAGE` / `LINE(n)` / `LINESIZE` / `PAGESIZE` / `TITLE` |
| 条件 | `ENDFILE(f)` / `UNDEFINEDFILE(f)`（ファイルごとに ON 単位を置ける） |
| 宣言 | `FILE` `STREAM` `RECORD` `INPUT` `OUTPUT` `UPDATE` `PRINT` `ENVIRONMENT` |

設計上の要点:

- **`ENDFILE` は ON 単位から復帰して実行を続ける。** 計算条件
  （FIXEDOVERFLOW など）と扱いが違う。`on endfile(sysin) done = '1'b;` と
  書いてループの判定に使う書き方がこれに依存する。
  一方 **`UNDEFINEDFILE` は ON 単位を実行したあと止まる**。復帰しても
  ファイルは開けていないので、続けると嘘の結果になる（`interp.ts` の `openFile`）
- **用途（`INPUT` / `OUTPUT`）は宣言した方が強い。** 暗黙 OPEN が渡すのは
  「今の使い方」（`PUT` なら output）なので、宣言より強く効かせると
  `INPUT` と宣言したファイルへの `PUT` が「出力で開く」になり、
  **実ファイルの中身を黙って破壊する**。食い違いは `UNDEFINEDFILE` にして、
  診断にどちらとどちらが食い違ったかを書く。`UPDATE` は読み書きの
  両方を受ける（`READ` と `REWRITE`）。`TITLE` や `PRINT` などの他の属性は
  `OPEN` に書いた方を採る（`streamio.ts` の `modeConflict`）
- **`ENDFILE` は「最後の項目を読んだ `GET`」で上がる。** そのとき値の代入は
  済んでいるので、`if ^done then put ...` と書くと**最後の 1 件を捨てる**。
  読めた値は必ず使い、ループを続けるかの判定にだけ `done` を使う
  （`InputCursor.atLastItem()`）。**実機で確かめた規則**で、項目の数より
  入力が少ないときは「末尾に届いた読み取り」と「データの無い項目」で
  **2 回**上がり、読めた分はそのまま代入される
  （golden の `getlist-exhausted` / `getlist-short`）
- **PRINT かどうかで書式が変わる。** PRINT は 24 桁タブストップと改ページ、
  PRINT でないストリーム出力は項目を空白 1 個で区切るだけ
- **行・桁の状態はファイルごとに持つ。** `LINESIZE` がファイル単位なので、
  `ListWriter` を 1 つ共有する作りでは成り立たない
- ファイル名は識別子なので `.` を含められない。ホストは `data` に対して
  `data.txt` / `data.dat` / `data.csv` を順に試す
- 閉じ忘れたファイルもプログラム終了時に書き戻す

## PICTURE

```pli
dcl amount pic'$$$,$$9V.99';
dcl count  pic'ZZZZ9';
dcl rate   pic'S9V.999';

amount = 1234.5;     /* 表示は " $1,234.50" */
amount = amount * 2; /* 算術にも使える。代入で再び編集される */
```

| 文字 | 意味 |
|------|------|
| `9` | 数字（ゼロも表示） |
| `V` | 小数点の位置（文字は出ない） |
| `Z` `*` | ゼロ抑制（空白 / アスタリスク詰め） |
| `$` `+` `-` `S` | 通貨記号と符号。2 個以上続けると**浮動**する |
| `.` `,` `/` `B` | 挿入文字（抑制された範囲では詰め文字になる） |
| `CR` `DB` | 末尾。負のときだけ出る |

- 内部は 10 進固定小数点。**表示のときだけ**編集を通すので、算術は
  通常の `FIXED DEC` と同じに書ける。結果にピクチャは伝わらない
- `$$$,$$9` のカンマは**浮動記号列の一部**。記号は最初の有効数字の
  直前（この例ではカンマの位置）に置かれる
- 桁に収まらない代入は **SIZE 条件**（`FIXEDOVERFLOW` ではない）
- 文字列との連結や `CHAR` への代入でも編集した形になる
- 対応しない指定（`A` `X` `E` `K` `T` `I` `R` `G` `M`）は宣言の時点で
  「使えない文字」として報告する

## BASED 記憶域とポインタ

```pli
dcl (head, cur) pointer;
dcl 1 node based(cur),
      2 value fixed bin(31),
      2 next  pointer;

head = null();
allocate node set(cur);
cur -> node.value = 10;
cur -> node.next = head;
head = cur;
/* 省略 */
free cur -> node;
```

| 対応 | 内容 |
|------|------|
| 宣言 | `POINTER` / `PTR`、`BASED(p)` / `BASED`、構造体ごと |
| 文 | `ALLOCATE x SET(p)` / `ALLOCATE x`、`FREE p -> x` |
| 参照 | `p -> x`、`p -> rec.field` |
| 組込 | `ADDR(x)`、`NULL()` |

**アドレス値は持たない。** ポインタは「確保した記憶域への参照」で、
算術（`p + 1`）も型の違う再解釈もできない。本物のアドレス空間を模すと
エミュレータを作ることになり、学習と検証という目的に費用が見合わない。
できないことははっきり断る方が、中途半端に動いて嘘の結果を出すよりよい。

代わりに**未定義動作になるものを必ず捕まえる**。

| 操作 | PL/I の規定 | この処理系 |
|------|------|-----------|
| NULL をたどる | 未定義動作 | 誤りとして止める |
| 解放済みをたどる | 未定義動作（たまたま動くこともある） | 誤りとして止める |
| 二重の FREE | 未定義動作 | 誤りとして止める |

`ADDR(x)` は変数のセルを共有するポインタを返すので、別名越しの
書き込みが元の変数に反映される。`ADDR` で取ったポインタを別の
`BASED` 宣言で見る場合、記憶域が 1 つしか持っていなければ
それを指しているとみなす（型の重ね合わせの簡易版）。

## レコード入出力

```pli
dcl inp file record input env(f recsize(13));
dcl 1 rec,
      2 name char(10),
      2 age  pic'999';
dcl done bit(1) init('0'b);

on endfile(inp) done = '1'b;
open file(inp) input title('IN.TXT');
read file(inp) into(rec);
```

| 文 | 内容 |
|----|------|
| `READ FILE(f) INTO(rec)` | 1 レコード読んで変数・構造体へ配る |
| `READ FILE(f) SET(p)` | 読んだレコードを指すポインタを設定する |
| `WRITE FILE(f) FROM(rec)` | 1 レコード書く |
| `REWRITE FILE(f) FROM(rec)` | 直前に読んだレコードを置き換える（UPDATE） |

**文字として表現できる項目だけを扱う。** 本来のレコードは記憶域そのもの
（packed decimal など）が入るが、仮想ファイルは文字列なので再現できない。
数値は `PICTURE` か文字で持つ。扱えない項目は黙って壊さず、
`RECORD 入出力で扱えません` と知らせる。

`ENVIRONMENT(F RECSIZE(n))` の固定長は、読むときに空白で埋め、
書くときに切り詰める。`KEY` 指定（索引ファイル）は未実装と報告する。

**レコードの区切りは行。** 実機は `RECSIZE` バイトずつ切って改行もデータとして
扱うが、ここでは 1 行を 1 レコードとする（理由は「実機と違えている点」）。
ただし `RECSIZE` より長い行は切り捨てずに `RECSIZE` ごとに切る。
切り捨てると残りが黙って消えるためで、この規則だと**改行の無いファイルは
実機と同じ結果**になる（`"abcdefgh"` を `RECSIZE(4)` で読むと `abcd` と `efgh`）。

## IMS/DB（DL/I）

使い方は [`../docs/dli.md`](../docs/dli.md)。ここは内部の作りと、
なぜその形にしたか。

```
src/macro.ts アセンブラのマクロ命令を読む（DBDGEN / PSBGEN / MFS で共用）
src/dli/
  types.ts   型と DliDefError
  dbd.ts     DBD → 階層の定義
  psb.ts     PSB → PCB の並びと感知セグメント
  ssa.ts     SSA の構文解析（誤りは例外ではなく値で返す）
  store.ts   階層セグメント記憶（木 + 階層順走査 + アンロード形式）
  dli.ts     エンジン本体（位置づけ・ステータスコード）
```

### 再現するのは論理層だけ

階層順・順序キー・位置づけ・ステータスコードは実機どおりに扱い、
物理層（HDAM の RAP、ポインタ、OSAM のデータセット）は再現しない。
`ACCESS=HDAM` でも `HIDAM` でも振る舞いは同じになる。業務プログラムから
見える違いはすべて論理層で決まるので、学習と検証の用には足りる。

**二次索引（`LCHILD` / `XDFLD`）・論理関係・`EXEC DLI`・
AIB インタフェース・同期点（`CHKP` / `ROLB`）は未実装**で、
当たると何が未実装かを名指しで断る。
IMS TM（メッセージキュー）と画面は別の層（`src/tm/` と `src/mfs/`）で
引き受ける。下の「画面入出力（MFS）と IMS TM」を参照。

### 実機と突き合わせられない

出力書式や精度規則は実在の PL/I 処理系の出力から導いているが、
DL/I にはそれができない（IMS は z/OS 専用で、手元のリファレンス実装に
DL/I は無い）。そこで DL/I は IBM の仕様文書を正とし、**各ステータス
コードの意味を `test/dli-engine.test.ts` のコメントに引用して**担保する。
処理系の他の部分とは担保の仕方が違う、という点は隠さずに書いておく。

### `BY ADDR` を一般実装しない

DL/I は出力パラメータが本質で、PCB のステータスコードとセグメント
I/O 領域を呼び先が書く。

ユーザー定義手続きの引数は**参照渡し**（PL/I の規定どおり）にしてあるが、
それは「変数そのものを渡したとき」に限る。DL/I は PCB マスクと
I/O 領域を**構造体で**渡し、呼び先が葉ごとに書き戻す。
ここで `BY ADDR` を一般実装すると、ダミー引数の作られ方まで含めて
手続きの意味論に手を入れることになる。そこで
**組込サブルーチンの呼び出しだけを特別扱い**した。
`interp.ts` の `case "call"` は、ユーザー定義の解決が空振りしたときだけ
`BUILTIN_SUBROUTINE_NAMES` を見て、引数を**値ではなく式のまま**
`plitdli()` へ渡す。書き戻しは `assign` / `leafCells` を通すので、
`SUBSTR` 疑似変数・`DEFINED`・`BASED`・配列要素がそのまま効く。

順序を「ユーザー定義 → 処理系」にしたのは、自分で `PLITDLI` という
手続きを書いて差し替えられる方が試しやすいため（IMS のプログラムを
単体試験するときの常用手法でもある）。

### PCB マスクは名前ではなく位置で結び付ける

PCB マスクの項目名はプログラムが自由に付けられる（`STAT_CODE` でも
`HOW_IT_WENT` でもよい）。一方 `basedCells` は記憶域を**葉の修飾名**で
引くので、処理系が先に PCB の記憶域を作っても名前が合わない。

そこで `Storage` に `pcbIndex` という印を足し、この印が付いた記憶域は
**葉の宣言順**で項目を結び付ける（`interp.ts` の `basedCells`、
`cells.size === 1` の抜け道より後ろに置く。前に置くと `ADDR` + 別名
`BASED` が壊れる）。実機が変位で重ねるのと同じ構図で、
ポインタがアドレスを持たない既存設計のまま成立する。

並びが規定より短ければ、いくつ必要かを言って断る。黙って短い宣言を
受けると、構造体でない宣言が暗黙宣言の経路に落ちて 0 が返り、
嘘の結果が出る。

### データは行指向のテキスト

`<DBD 名>.dat` は 1 行 1 セグメント出現で、先頭 8 桁がセグメント名。
**階層は行の順で決まる**（子の親は直前に現れた親の型の出現）。
これは IMS の階層順そのものなので、形式のために新しい規則を作らずに済む。
人が読めて diff も取れ、ブラウザの仮想ファイルでそのまま編集できる。
既存の「レコードは行」という入出力の方針とも揃う。

JSON を採らなかったのは、この処理系のファイルがすべてプレーンテキストで、
ブラウザ版のファイル編集画面と Linter / テストの流儀に合わせるため。

### 作る途中でつまずいた点

- **親の確立を GNP が動かしてはいけない。** 動かすと配下の走査が
  1 段ずつ潜っていき、2 件目で止まる。親は `GU` / `GN` が確立する
- **`GA` と `GK` は警告で、セグメントは返る。** `stat_code = '  '` を
  ループ条件にすると階層をまたいだところで読み落とす。
  サンプルも例も `stat_code ^= 'GB'` を条件にしてある
- **SSA の桁。** 項目名 8 桁 + 関係演算子 2 桁なので、`STUDNO`（6 文字）
  と `=` の間の空白は 3 つになる。ここを 2 つにすると演算子が `=S` と
  読まれて `AJ` になる。実際に最初のテストでこれを踏んだ
- **`scatterRecord` / `gatherRecord` を流用できない。** あの 2 本は
  `v.cells[0]` に直接書くので `BASED` の葉を無視する（`cells` が空）。
  書き込みが静かに消えるため、セグメント I/O 領域は `leafCells` 経由で扱う
- **Linter に引数の向きを教える必要がある。** PCB は出力、
  セグメント I/O 領域は入出力、機能コードと SSA は入力。向きを無視すると
  「代入していない」「代入したが読んでいない」を誤検出する
- **テストランナーがデータを壊した。** `plitest` が `DLET` の更新を
  実ファイルへ書き戻し、`examples/tests/STUDENT.dat` が実際に消えて
  2 回目から結果が変わった。既定で書き戻さないようにした（`--write` で反映）

## 画面入出力（MFS）と IMS TM

使い方は [`../docs/mfs.md`](../docs/mfs.md)。ここは内部の作りと、
なぜその形にしたか。

```
src/mfs/
  blocks.ts  MID / MOD / DIF / DOF の型と、名前で引く表
  source.ts  書式定義（FMT / MSG）を読む
  device.ts  3270 の画面の器（位置・属性・隙間の項目）
  output.ts  MOD + DOF → 画面
  input.ts   DIF + MID → セグメント
  render.ts  画面 → テキスト（テストと CLI の表示用）
  check.ts   止めるほどではない、たぶん間違いの点検
src/tm/
  tm.ts      メッセージキュー（GU / GN / ISRT / PURG とステータスコード）
  session.ts 画面との往復（1 入力 = 1 回の実行）
  keys.ts    端末の操作の台本と、その記録
```

### 1 回の入力 = 1 回のプログラム実行

画面入出力は「出す → 人が打つ → 続ける」なので、素直に作ると実行器を
止める必要がある。次の 4 案のうち **D** を採った。

| 案 | 内容 | 判定 |
|----|------|------|
| A | 実行器を生成器 / async にする | 却下。`interp.ts` の評価経路すべてに `yield` が伝播する |
| B | Worker + `SharedArrayBuffer` で待つ | 却下。COOP/COEP ヘッダが要る＝サーバが必要になり、「HTML 1 枚で動く」が壊れる |
| C | 入力が増えるたび先頭から再実行する | 却下。データベースの更新が二重にかかる |
| D | **1 入力 = 1 回の実行** | 採用 |

**D が正しいのは実機の MPP がそう動くから。** `GU` がキューから 1 件取り、
処理し、`ISRT` で返し、キューが空なら `QC` で終わる。画面と画面の間で
プログラムは生きておらず、会話の状態を持つのは IMS 側（SPA）。
だから同期的な実行器のままで足りる。**実機でもできないこと**
（1 回の実行の中で人と往復する）は、ここでもできない。

### 画面は項目の単位まで。データストリームは作らない

本物の 3270 のデータストリーム（`SBA` / `SF` / `IC` の並び、AID と
read modified の byte 列）は作らない。**確かめる手段が無いから。**
IMS は z/OS 専用で、手元で動かせる実装が無い。確かめられないものを
byte 単位で固めると、間違った値を固めても気づけない。業務プログラムから
見えるのはセグメントであってデータストリームではないので、項目の単位まで
再現すれば足りる。

ただし後から足せる形にしてある。画面は「位置と属性と中身を持つ項目の並び」
なので、直列化器を 1 つ書けばデータストリームにできる。

### 実機の規則のうち、見落としやすいもの

- 属性バイトは `POS` の 1 つ前を食う。1 桁目から始まる項目の属性バイトは
  前の行の末尾に乗る（線形の番地で数えているのはこのため）
- 定義された項目が 2 桁以上あいた隙間には `NUM, PROT, NODISP` の項目ができる
- 同じ書式が装置に入っているなら、書き換えは MOD が触る項目だけ
  （メッセージ書き出し）。打ち込んだ値が返ってきた画面に残るのはこのため
- 書き出しのたびに変更の印（MDT）は落ちる。打ち直さなければ次は返らない
- 読むのは変更の印が立った項目だけで、末尾の空白は落とす。
  落とさないと `JUST=R` と `FILL=` が効かない

### 期待値の出どころ

DL/I と同じで、突き合わせる実機が無い。IBM の仕様文書を正とし、
根拠をテストに引用する。画面像のゴールデンは実機由来のもの
（`test/golden/`）と混ざらないよう `test/screen/` に分け、
`.why` の 1 行目を「IBM 仕様に基づく（実機の出力ではない）」で
始めることをテストで確かめている。

## Linter

構文は通るが怪しい書き方を指摘する。詳細は [`../docs/lint.md`](../docs/lint.md)。

```bash
npm run plilint -- examples/tests       # ディレクトリを再帰的に
npm run plilint -- --list-rules         # 規則と、その理由
```

主目的は **`implicit-declaration`**。PL/I は宣言の無い名前を暗黙に宣言する
（`I`〜`N` は `FIXED BIN(15,0)`、他は `FLOAT DEC(6)`）ため、綴り間違いが
黙って別の変数になり、誤った値のまま動き続ける。予約語が無い言語なので、
この種の誤りを機械が拾う価値が特に高い。

誤検出が出た時点で Linter は切られる。ブラウザ版のサンプル 13 本と
`examples/tests` に対して**指摘 0** であることをテストで固定している。

## Snippet

43 本の Snippet を `src/snippets.ts` に定義している。**定義源はここだけ**で、
VSCode 用の `snippets/pli.json` は生成物である。

```bash
npm run gen:snippets   # ../vscode-pli/snippets/pli.json を書き出す
```

同じ定義をブラウザ版のヘッダの「Snippet…」からも挿入できる。
VSCode の Snippet 記法（`${1:名前}`）は `plainText()` で落としてから挿入し、
2 行目以降は挿入位置の字下げに合わせる。

全 Snippet が**解析できること**と、`standalone` 印のあるものは
**挿入しただけで実行できること**をテストで確かめている（43 件）。
Snippet が PL/I として壊れていても気付けない状態を避けるため。

## テストフレームワーク

PL/I で書いたテストを PL/I で走らせる。詳細は [`../docs/test.md`](../docs/test.md)。

```pli
/* math_test.pli — 主手続きは書かない */
SETUP: proc;
  /* 各テストの前に走る */
end SETUP;

TEST_DECIMAL_IS_EXACT: proc;
  dcl x fixed dec(5,2);
  x = 0.1;
  x = x + 0.2;
  call ASSERT_EQUALS(0.3, x, '10進なら誤差が出ない');
end TEST_DECIMAL_IS_EXACT;
```

```bash
npm run plitest -- examples/tests            # ディレクトリをまとめて
npm run plitest -- math_test.pli --xml out # CI 用の XML も出す
```

失敗・異常が 1 件でもあれば終了コード 1 を返すので、そのまま CI に載せられる。

決めごとは、`ASSERT_EQUALS(期待, 実際, 説明)` の引数順、表明の失敗で
即中断すること、failure（表明の失敗）と error（想定外の異常）の区別、
`SETUP` / `TEARDOWN`、`DISABLED_` 接頭辞、CI 用の XML 出力。

**全体の前後に一度だけ走る仕掛けは意図的に持たない。** テストは 1 件ずつ
別のプログラムとして実行するので、複数のテストにまたがる状態が存在せず、
「一度だけ」という約束を果たせない。守れない約束を API として置く方が
害が大きいと判断した。

## 利用側

入口はいくつかあるが、どれも `src/index.ts` が公開するものだけを使い、
Node 依存は無い（CLI だけは当然ファイルを読む）。

`src/index.ts` は 7 つの実体をまとめただけの窓口である。

| 実体 | 役目 |
|------|------|
| `src/run.ts` | ソースを実行して診断を返す |
| `src/host.ts` | 外界（`%INCLUDE` とファイル）への差し込み口 |
| `src/lint.ts` | 構文は通るが怪しい書き方を指摘する |
| `src/snippets.ts` | Snippet の定義（単一の定義源） |
| `src/testing.ts` | テストフレームワーク |
| `src/mfs/` | 画面の書式（MID / MOD / DIF / DOF）と画面そのもの |
| `src/tm/` | メッセージキューと、画面との往復 |

`testing.ts` が `run.ts` を使うため、循環参照を避けて
実行の層は `index.ts` から分けてある。

| 入口 | 場所 | 説明 |
|------|------|------|
| ブラウザ版 | [`web/`](web/README.md) | **HTML 1 枚**。ダブルクリックで開くだけ。サーバ不要・オフライン可 |
| VSCode Extension | [`../vscode-pli/`](../vscode-pli/README.md) | 構文強調・診断・実行・テスト・Snippet。処理系を同梱 |
| テストの CLI | `scripts/plitest.ts` | `npm run plitest -- <ファイル/ディレクトリ>` |
| Linter の CLI | `scripts/plilint.ts` | `npm run plilint -- <ファイル/ディレクトリ>` |
| 画面の CLI | `scripts/pli.ts --keys` | `npm run pli -- <ファイル> --psb <名前> --keys <台本>` |

### 公開 API

```ts
// npm には公開していない（package.json は private）。
// 利用側はリポジトリ内から相対で読む
import { runProgram } from "../engine/src/index.js";

const r = runProgram(source, {
  args: ["123"],           // 主手続きの引数
  maxSteps: 5_000_000,     // 無限ループ対策
  maxOutputBytes: 1_000_000,
});
// r.ok / r.stdout / r.diagnostics[] / r.truncated / r.durationMs
```

診断は `{ severity, phase, line, col?, message }` の配列で返る。
`phase` は `preprocess` / `lex` / `parse` / `runtime` のいずれか。

ブラウザには別プロセスが無いため、**無限ループはエンジン側で止める**。
文の数を数えるだけでなく、本体が空のループ（`do while('1'b); end;`）でも
止まるようループの周回でも数えている。
