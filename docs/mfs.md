# 画面入出力（MFS）

PL/I から**3270 の画面**を読み書きできる。IMS をインストールする必要は無い。
書式定義（`*.mfs`）はテキストで、ブラウザ版なら「ファイル」欄に書いて
「端末」を開くだけで動く。

```
INVFMT   FMT
         DEV   TYPE=3270-A2,FEAT=IGNORE
         DIV   TYPE=INOUT
         DPAGE CURSOR=((5,20))
         DFLD  'ITEM NO:',POS=(5,10),ATTR=(ALPHA,PROT)
ITEMIN   DFLD  POS=(5,20),LTH=6,ATTR=(NUM,NOPROT,HI)
NAMEOUT  DFLD  POS=(7,20),LTH=20,ATTR=(ALPHA,PROT)
PFKEY    DFLD  POS=(24,2),LTH=12
         FMTEND
INVIN    MSG   TYPE=INPUT,SOR=(INVFMT,IGNORE),NXT=INVOUT
         SEG
         MFLD  (PFKEY,'INVQ        '),LTH=12
         MFLD  ITEMIN,LTH=6,JUST=R,FILL=C'0'
         MSGEND
INVOUT   MSG   TYPE=OUTPUT,SOR=(INVFMT,IGNORE),NXT=INVIN
         SEG
         MFLD  NAMEOUT,LTH=20
         MSGEND
```

プログラムは**画面を知らない**。読み書きするのはセグメント（`LL ZZ` と
データ）だけで、どの桁に何を出すかは書式定義が決める。これが MFS の役目。

## 4 つの制御ブロック

| ブロック | 正式名 | 役目 | どの文から作られるか |
|---------|-------|------|--------------------|
| **MID** | Message Input Descriptor | 装置から来たものをプログラムが見る形に組む | `MSG TYPE=INPUT` … `MSGEND` |
| **MOD** | Message Output Descriptor | プログラムが書いたものを装置向けに配る | `MSG TYPE=OUTPUT` … `MSGEND` |
| **DIF** | Device Input Format | 装置から来るデータの形 | `FMT` 内の `DIV TYPE=INPUT` / `INOUT` |
| **DOF** | Device Output Format | 装置へ送る画面の形 | `FMT` 内の `DIV TYPE=OUTPUT` / `INOUT` |

4 つで 1 組。`DIV TYPE=INOUT`（3270 表示装置の定石）だと 1 つの `FMT` から
DIF と DOF の両方ができる。

```
入力   端末 → [DIF] 位置→項目 → [MID] 項目→セグメント → GU / GN
出力   ISRT → [MOD] セグメント→項目 → [DOF] 項目→位置 → 画面 → 端末
```

## 1 回の入力 = 1 回のプログラム実行

**画面と画面の間でプログラムは生きていない。** 実機の MPP と同じで、
`GU` がキューから次のメッセージを取り、処理し、`ISRT` で返し、
キューが空になれば `QC` を返して終わる。

引き継がれるのは次の 3 つだけ。

| 引き継がれるもの | 持ち主 |
|----------------|-------|
| データベースの中身 | ホスト（実行の終わりに書き戻る） |
| 会話の状態 | SPA。**プログラムではなく IMS 側**が持つ |
| 次に読む書式 | 直前に送った MOD の `NXT=` |

この形にしてあるので、実行器を止めて人の入力を待つ必要がない。
ブラウザで待とうとすると Worker と `SharedArrayBuffer` が要り、
そのためのヘッダ（COOP/COEP）はサーバを必要とするので、
「HTML 1 枚で動く」という前提が壊れる。
**実機でもできないこと**（1 回の実行の中で人と往復する）は、ここでもできない。

## 何を再現し、何を再現しないか

| 再現する | 再現しない |
|---------|-----------|
| 項目の位置・長さ・属性（保護 / 数字 / 強調 / 非表示） | **本物の 3270 データストリーム**（`SBA` / `SF` / `IC` の並び） |
| 属性バイトが 1 つ前の位置を食う規則 | tn3270 との接続、実機の端末 |
| 変更の印（MDT）と read modified | DBCS / EGCS、プログラムシンボル、項目の外枠 |
| `JUST` / `FILL` / 切り捨て、固定文字、システム定数 | 論理ページング（`MSG PAGE=YES`）と物理ページング（PA1） |
| `DO` / `ENDDO` の繰り返しと通し番号 | 分割画面（3290 のパーティション） |
| PF キーの割り当て、`DSCA`、`ATTR=YES` | `OPT=2` / `OPT=3`、`PASSWORD`、`TABLE` / `PDB` |
| メッセージキュー（`GU` / `GN` / `ISRT` / `PURG`） | 代替 PCB（`CHNG` / `ISRT` の送り先変更） |
| 会話型（SPA）、`/FORMAT` | `/FORMAT` 以外の IMS コマンド、MFS の EXIT ルーチン |
| `CLEAR`（緩衝を消して AID だけ送る） | PA1〜PA3（物理ページング） |
| `DEV SYSMSG=`（IMS の通知をその項目に出す） | `DFLD EATTR=`（色・下線などは画面像に出ない。点検が警告する） |

**本物のデータストリームを作らない理由。** この処理系の出力書式と精度は
実在の PL/I 処理系と突き合わせて決めているが、MFS にはそれができない
（IMS は z/OS 専用で、手元で動かせる実装が無い）。確かめる手段が無いものを
byte 単位で固めると、**間違った値を固めても気づけない**。
業務プログラムから見えるのはセグメントであってデータストリームではないので、
項目の単位まで再現すれば足りる。

再現しないものに当たったときは、**名指しで断る**。黙って別の結果を返さない。

## 書式定義の文

| 文 | 主なオペランド | 備考 |
|----|--------------|------|
| `FMT` / `FMTEND` | （ラベルが書式の名前） | |
| `DEV` | `TYPE=`、`FEAT=IGNORE`、`PFK=`、`DSCA=`、`SYSMSG=` | `TYPE` は `3270-A1`（12×40）/ `A2`（24×80）/ `A3`（32×80）/ `A4`（43×80）、`3270,1`（12×40）、`3270,2`、`3270`（どちらも 24×80）。**`DEV` は 1 つだけ**（装置ごとに並べる形は未実装）。`PFK=` は固定文字を入れる項目名が必須 |
| `DIV` | `TYPE=INOUT` / `INPUT` / `OUTPUT` | 3270 では `INOUT`（既定） |
| `DPAGE` | `CURSOR=((行,桁))`、`FILL=` | 1 つだけ（ページングが未実装）。`FILL=` は `C'c'` / `X'40'`（空白）/ `X'00'`・`NULL`（埋めない）。他の `X'hh'` は EBCDIC の対応表を持たないので断る |
| `DFLD` | 固定文字、`POS=(行,桁)`、`LTH=`、`ATTR=`、`EATTR=` | ラベルがあると MFLD から指せる（**書式の中で一意**）。`POS=(1,1)` は書けない（属性バイトの置き場所が無い）。`EATTR=` は読むが画面像に出ない |
| `DO` / `ENDDO` | 回数、行の増分、桁の増分、`SUF=` | 入れ子は不可。回数は 99 まで。繰り返す `DFLD` のラベルは 6 桁まで（通し番号 2 桁が付く）。位置はカンマを続けて省ける（`DO 3,,5` は桁の増分 5） |
| `MSG` / `MSGEND` | `TYPE=`、`SOR=`、`NXT=`、`OPT=1`、`FILL=` | `SOR=` は必須。`TYPE=` の既定は `INPUT` |
| `LPAGE` | （オペランド無し） | 1 つだけ（`COND=` が未実装のため）。省くと 1 つとして扱う |
| `SEG` | （オペランド無し） | 省くと 1 つとして扱う |
| `MFLD` | 項目名 / 固定文字 / `(項目,'固定文字')` / `(項目,DATE2)`、`LTH=`、`JUST=`、`FILL=`、`ATTR=` | `JUST=` の既定は `L`。システム定数は `DATE1`（6 桁）/ `DATE2` / `DATE3` / `DATE4` / `TIME` / `LTNAME`（各 8 桁）の 6 つで、**出力の MSG でしか使えない** |

書式はアセンブラのマクロ命令（DBDGEN / PSBGEN と同じ）。
1 桁目が `*` なら注釈、72 桁目が非空白なら次の行へ継続して 16 桁目から続く。
行頭の空白の数は問わない。

**オペランドの後の空白から先は注釈。** そのため
`DFLD POS=(1,2),LTH=5, ATTR=(ALPHA,PROT)` のようにカンマの後に空白を
入れると、以降が注釈になって `ATTR=` が消える。黙って既定値
（打ち込める項目）に落ちると気づけないので、**この形は誤りとして断る**。
カンマの後は空白を入れずに続けるか、72 桁目に継続の印を付ける。

**位置オペランドはカンマを続けて省ける。** `DO 3,,5` は
「回数 3 / 行の増分は既定 / 桁の増分 5」で、項目が横に並ぶ。

`ATTR=` を省いたときは **ALPHA・NOPROT・NORM・NOMOD**。

## プログラムの書き方

入出力 PCB は PSB の先頭に置く（`PCB TYPE=TP`、または `CMPAT=YES`）。

```
         PCB  TYPE=TP
         PSBGEN LANG=PLI,PSBNAME=INVPSB
         END
```

主手続きはその順でポインタを受ける。

```pli
invq: proc(io_ptr) options(main);
  dcl plitdli entry;
  dcl io_ptr pointer;
  dcl 1 io_pcb based(io_ptr),
        2 lterm_name char(8),      /* 論理端末名 */
        2 reserved1  char(2),
        2 stat_code  char(2),      /* ステータスコード */
        2 msg_date   fixed dec(7,0),   /* ユリウス日 yyddd */
        2 msg_time   fixed dec(7,1),   /* hhmmss.t */
        2 msg_seq    fixed bin(31),
        2 mod_name   char(8),      /* MFS が使う出力書式 */
        2 user_id    char(8);
  dcl 1 msg_in,
        2 in_ll   fixed bin(15),   /* LL ZZ を含めた長さ */
        2 in_zz   fixed bin(15),
        2 in_tran char(12),
        2 in_item char(6);
  dcl 1 msg_out,
        2 out_ll   fixed bin(15),
        2 out_zz   fixed bin(15),
        2 out_name char(20);
  dcl three fixed bin(31) init(3);
  dcl four  fixed bin(31) init(4);
  dcl func_gu   char(4) init('GU  ');
  dcl func_isrt char(4) init('ISRT');
  dcl modname   char(8) init('INVOUT  ');

  call plitdli(three, func_gu, io_pcb, msg_in);
  do while (io_pcb.stat_code = '  ');
    msg_out.out_name = 'BOLT ' || msg_in.in_item;
    msg_out.out_ll = 24;                     /* 4 + 20 */
    msg_out.out_zz = 0;
    call plitdli(four, func_isrt, io_pcb, msg_out, modname);
    call plitdli(three, func_gu, io_pcb, msg_in);
  end;
end invq;
```

データベースも併せて使うなら、入出力 PCB の**後ろ**に DB PCB を並べ、
主手続きでその順にポインタを受ける。**動く一式**（`.pli` / `.mfs` /
`.psb` / `.dat` / 台本）は `engine/test/screen/dbinq.*` にある。

要点が 4 つある。

1. **メッセージ I/O 領域の先頭 2 項目は `LL` と `ZZ`**。どちらも
   `FIXED BIN(15)` で宣言する。`LL` には `LL ZZ` の 4 バイトを含めた
   長さを入れる。入れ忘れると名指しで断る（黙って空の画面が出ない）。
2. **送るのは `LL` の分だけ。** 領域の後ろは切る（実機も `LL` を見る）。
3. **出力の書式は `ISRT` の 4 つめの引数**（機能コードから数える。
   `CALL` の括弧の中では 5 番目）。省くと入力の MID の `NXT=` になる。
4. **構造体の項目は「親.項目」で書く。** この処理系は項目だけを書くと
   別の変数として暗黙に宣言する。Linter の `unqualified-member` が指摘する。

### 入出力 PCB のステータスコード

| コード | 意味 | どの呼び出しで |
|-------|------|--------------|
| 空白 2 つ | 取れた / 入った | 全部 |
| `QC` | キューにメッセージが無い（プログラムの終わり） | `GU` |
| `QD` | このメッセージにこれ以上セグメントが無い | `GN` |
| `QE` | `GU` より先に `GN` を出した | `GN` |
| `AD` | 機能コードが正しくない。`GHU` / `GHN`（ホールド付き検索はデータベース PCB だけの機能） | 全部 |

次の呼び出しは**名前は知っていて、使うと「未実装」と断る**。
`CHKP` / `XRST` / `ROLB` / `ROLL` / `ROLS` / `SETS` / `LOG` / `STAT` /
`SNAP` / `GSCD` / `APSB` / `DPSB` / `CHNG` / `SETO` / `CMD` / `GCMD` /
`AUTH` / `INIT`。黙って `AD` を返すと書き間違いと区別が付かないため。

`GU` / `GN` / `ISRT` には**必ず I/O 領域を渡す**。渡さないと名指しで断る
（以前は成功を返してキューを 1 件進めていたので、入力が消えていた）。

## 動かす

### ブラウザ版

付随ファイルに `::: 名前.mfs` で書式定義を、`::: 名前.psb` で PSB を置き、
ヘッダの「端末」を押す。「最初の画面」に MOD の名前を入れて「開始」。
打ち込める項目には入力欄が重なるので、そこへ打って ENTER。
PF キーは右の一覧から選んで「送信」。

サンプル「画面入出力（MFS）＋ IMS/DB」を選ぶと、一式が入って端末が開く。

### CLI

端末のかわりに**台本**を流す。

```
npm run pli -- invq.pli --psb INVPSB --keys invq.keys
```

書式定義はソースと同じディレクトリの `*.mfs` を全部読む
（`--mfs` で名指しもできる）。

### VSCode

コマンド「PL/I: 画面を動かす（MFS）」。書式定義と台本はソースと同じ
場所から読み、画面像を出力パネルに出す。編集中で未保存のものは
その内容を使う。

## 台本（`*.keys`）

```
MOD   INVOUT                 最初に出す画面（端末で /FORMAT と打つ代わり）
SPA   20                     会話型トランザクションの SPA の長さ（5 以上）
LTERM TERM0001               論理端末名
USERID TSO0001               利用者名（入出力 PCB の USER_ID）
NOW   2026-10-10T15:04:05    時刻（書かないと固定できない）
ITEMIN=42                    項目に打ち込む
ENTER                        送る
PF3                          PF キーで送る（PF1〜PF24）
CLEAR                        CLEAR キーで送る
NEXT                         溜まっている次のメッセージを出す
```

行頭の `*` と `#` は注釈。**時刻は必ず書く**。`DATE2` や `TIME`、
入出力 PCB の日付は与えた時刻から作るので、書かないと実行のたびに変わる。

## 忘れると嵌まる規則

- **属性バイトは `POS` の 1 つ前の位置を食う。** `POS` と `LTH` は属性バイトを
  数えない。1 桁目から始まる項目の属性バイトは**前の行の最後のバイト**に乗るので、
  **`POS=(1,1)` は書けない**（置き場所が無いと言って断る）。
  項目の間は 1 桁以上あける。
- **定義された項目が 2 桁以上あいていると、MFS が隙間の項目を作る**
  （`NUM, PROT, NODISP`）。打ち込める項目の後ろの空きに打てないのはこのため。
- **埋め文字の出どころが入力と出力で違う。** 入力（装置 → セグメント）は
  `MFLD` の `FILL=`、出力（セグメント → 画面）は `DPAGE` の `FILL=`、
  無ければ `MSG` の `FILL=`、どちらも無ければ空白。
- **変更していない項目は装置から返ってこない**（MDT）。返らなかった項目は
  `MFLD` の `FILL=` で埋まり、`FILL=NULL` ならセグメントから消える。
  **書き出しのたびに変更の印は落ちる**ので、打ち直さなければ次は返らない。
- **装置から返るとき、項目の末尾の空白は落ちる。** 6 桁の項目に `42` と
  打つと `42` が届き、`JUST=R` と `FILL=C'0'` で `000042` になる。
  落とさないとこの 2 つが効かない。
- **プログラムが異常終了したら出力を捨てる。** `ISRT` を済ませてから落ちても
  画面は変わらない。実機の MPP が落ちると IMS は直前の同期点まで戻して
  出力メッセージを捨てるため。**データベースの更新は残る**
  （ファイルと同じ約束。MPP の同期点は再現しない）。
- **トランザクションコードは PF キーの仕掛けで入れる。** `MFLD (項目,'INVQ')`
  と書くと、その項目に何も来なかったとき（= ENTER のとき）固定文字が入る。
  `DEV PFK=(項目,3='/FOR MENU.')` と書けば PF3 でその固定文字が入る。
  **コマンドはピリオドで終える**（項目の中身はセグメントの中で隣とくっつく）。
- **同じ書式が装置に入っているときは、書き換えは MOD が触る項目だけ**
  （メッセージ書き出し）。固定文字から組み直すのは書式が変わったとき、
  `DSCA` で強制書き出しを指定したとき、`/FORMAT` を打ったときだけ。
  打ち込んだ値が返ってきた画面に残っているのはこのため。
- **`FILL=NULL` の扱いは実機と少し違う。** 実機のナルは「その桁を送らない」
  ＝装置の表示を変えないが、この処理系は空白で埋める（書式書き出しなら
  元が空白なので同じ結果、メッセージ書き出しでは項目の残りが消える）。
  入力側も、**何も返らなかった項目**はセグメントから消えるが、
  **短いデータが返った項目**は空白まで伸ばす（桁割りを固定に保つため）。
- **項目は行をまたげない。** 実機の緩衝は線形なのでまたげるが、この処理系は
  定義の時点で断る（`LTH` か `POS` の書き間違いがほとんどで、画面像を
  行ごとに見せる作りでは読みにくくなるため）。行ごとに分けて定義する。
- **全角文字は 1 桁として数える。** DBCS を再現しないので、画面像の桁は
  定義どおりだが、等幅で表示すると見た目はずれる。

## 書式定義の点検

読んだ時点で断るのは「画面が組めない誤り」（項目の重なり、参照先が無い、
画面の外、ラベルの重複など）。それ以外に、**定義としては通るが動かして
初めて困るもの**を警告として出す。CLI は標準エラーへ、ブラウザ版は
「書式の指摘 N 件」、VSCode は出力パネルに `[書式]` 付きで出す。

| 警告 | 直し方 |
|------|-------|
| 入力に使う書式に打ち込める項目が 1 つもない | `ATTR=` の `PROT` を外す。見出しだけの書式を MID の `SOR=` にしていないか確かめる |
| `DPAGE CURSOR=` の位置に項目が無い / 保護された項目を指している | 項目の**先頭**の行・桁を指す。打ち込める項目にする |
| どの `MFLD` からも指されていない `DFLD` | 名前の綴りを確かめる。表示だけの項目ならラベルを外す |
| `EATTR=` は画面像に出ない | 色・下線は再現しないので、必要なら `ATTR=` の `HI` で代える |

## 会話型（SPA）

`TRANSACT SPA=` にあたる長さを与えると会話型になる（CLI と VSCode では
台本の `SPA`）。実機ではシステム定義が決めるもので、プログラムにも
メッセージにも書かれていないので、こちら側で与える。

**ブラウザ版の端末は台本を使わないので、会話型は動かせない。**
SPA の長さを与える口が無い。CLI か VSCode で試す。

SPA の形は **`LL`(2) + `ZZZZ`(4) + トランザクションコード(8) + 作業域**。
先頭 6 桁はプログラムが触ってはならない。

```pli
  dcl 1 spa,
        2 s_ll   fixed bin(15),
        2 s_zz   fixed bin(15),
        2 s_zz2  char(2),          /* ZZZZ の残り */
        2 s_tran char(8),
        2 s_save char(6);          /* 作業域 */
```

会話型のプログラムは **`GU` で SPA を取り、`GN` で入力を取り、
最初に SPA を `ISRT` してから**画面用のセグメントを `ISRT` する。
**トランザクションコードを空白にして返すと会話が終わる。**

最初の `ISRT` が SPA の形（`SPA` で与えた長さ − 4 桁）でなければ断る。
黙って先頭のセグメントを SPA と見なすと、画面用のセグメントが SPA に
化けて次の入力として戻ってくる。

## 期待値の出どころ

MFS と DL/I には**突き合わせる実機が無い**。IMS は z/OS 専用で、
手元で動かせる実装（商用の移行製品しかない）も入手できない。
